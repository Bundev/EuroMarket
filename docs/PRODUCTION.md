# Запуск EuroMarket через HTTPS

## Локальная разработка

Заполните пустые значения в копии `.env.example` или используйте свою локальную
конфигурацию. Для `SESSION_SECRET` используйте случайный секрет длиной не менее
32 байт. `npm start` открывает `http://localhost:3000` при стандартных настройках.
Локальные cookies используют HttpOnly и SameSite=Lax. Secure и HSTS включаются
в production.

## Production

1. Установите зависимости из lockfile командой `npm ci --omit=dev`. Подготовьте
   MariaDB. Для новой базы используйте `database/schema.sql`. В существующей
   базе сначала сделайте резервную копию и примените отсутствующие миграции из
   `database/migrations`. Проверьте наличие `sessions`, миграции 006
   (`auth_rate_limits`) и миграций 007 (`deals`) и 008 (`reviews`,
   `review_reports`, тип уведомления `review`), 009 (предварительная модерация),
   011 (уведомления о сделках), 012 (история сделок), 013 (споры и закрытые
   фотографии доказательств), 014 (подписки и очередь публикаций) и 015
   (сохранённые поиски) и 016 (история просмотров).
   Миграцию 014 применяйте при остановленных процессах приложения. Для обработчика
   нужна MariaDB 10.6 или новее с поддержкой `FOR UPDATE SKIP LOCKED`.
   Обработчик запускается вместе с приложением. Несколько экземпляров могут
   обрабатывать разные задачи, максимум по 200 подписок и 200 сохранённых
   поисков за транзакцию. Применяйте миграцию 015 до запуска новой версии.
   Для вложений нужен `max_allowed_packet` не менее
   4 МиБ. Закрытые фотографии входят в резервную копию MariaDB.
   Запуск сервера проверяет
   эти таблицы. Приложение в production использует учётную запись с правами
   чтения и необходимыми правами записи, без DDL. Миграции выполняются
   отдельной учётной записью.
2. Передайте настройки через окружение сервиса или отдельный защищённый файл.
   Заполните `DB_HOST`, `DB_USER`, `DB_NAME` и `DB_PASSWORD` для целевой
   MariaDB. `DB_PORT` по умолчанию 3306. Задайте уникальный
   случайный `SESSION_SECRET`. Используйте один и тот же секрет на всех
   экземплярах. Храните его в хранилище секретов. Выключите `DEBUG` и
   `NODE_DEBUG`.

   ```dotenv
   NODE_ENV=production
   BIND_HOST=127.0.0.1
   PORT=3000
   AUTH_RATE_STORE=mariadb
   TRUSTED_PROXIES=127.0.0.1/32
   CSP_MODE=report-only
   PUBLIC_ORIGIN=https://market.example.com
   ```

3. Оставьте порт Node.js доступным только reverse proxy. Для прокси на другой
   машине задайте адрес приватного интерфейса в `BIND_HOST`, разрешите вход
   с адреса этого прокси через firewall и перечислите его точный IP в
   `TRUSTED_PROXIES`. Для примера ниже Node.js и Nginx находятся на одном хосте.
4. Получите действующий сертификат для своего домена и настройте продление.
   Пример Nginx для одного публичного прокси. Замените домен и пути сертификатов.

   ```nginx
   server {
       listen 80;
       server_name market.example.com;
       return 308 https://market.example.com$request_uri;
   }
   server {
       listen 443 ssl;
       server_name market.example.com;
       ssl_certificate     /etc/ssl/market/fullchain.pem;
       ssl_certificate_key /etc/ssl/market/privkey.pem;
       ssl_protocols TLSv1.2 TLSv1.3;
       server_tokens off;
       client_max_body_size 52m;
       client_body_timeout 30s;

       location / {
           proxy_pass http://127.0.0.1:3000;
           proxy_http_version 1.1;
           proxy_set_header Connection "";
           proxy_set_header Host market.example.com;
           proxy_set_header X-Forwarded-Host market.example.com;
           proxy_set_header X-Forwarded-Proto https;
           proxy_set_header X-Forwarded-For $remote_addr;
           proxy_set_header Forwarded "";
           proxy_read_timeout 60s;
       }
   }
   ```

   Перезаписывайте заголовки прокси, которые прислал клиент. При использовании
   CDN или цепочки прокси настройте доверие по каждому переходу и проверьте
   фактический адрес клиента для лимитов. Передавайте все URL приложению.
   Сохраните защищённый маршрут `/uploads/listings/` и храните оригиналы вне
   любых публичных каталогов веб-сервера. Резервируйте хранилище фотографий и
   MariaDB вместе. Для нескольких экземпляров обеспечьте общее постоянное
   хранилище либо согласованную выдачу фотографий.
5. Выполните `nginx -t`, запустите `npm start` из каталога EuroMarket под менеджером сервисов и проверьте
   внешний HTTPS. Для SIGTERM/SIGINT предоставьте процессу минимум 15 секунд
   до принудительного завершения. Node-супервизор на Windows может передать
   сообщение `shutdown` по IPC. Настройте регулярный запуск
   `node scripts/prune-auth-rate-limits.js` с доступом только к нужной базе.
6. Проверьте `Set-Cookie` на `/login` и после входа, CSRF-запросы, HSTS,
   404/500, поиск, фото, уведомления, сделки и админку. Убедитесь, что прямой
   доступ к порту Node.js закрыт извне.

## Включение CSP

Первый запуск использует `Content-Security-Policy-Report-Only`. Проверьте
нарушения в консоли браузера на страницах для гостя, пользователя и администратора.
Проверьте селекты Tom Select, предпросмотр фотографий, галерею, мобильное меню
и AJAX. Политика разрешает JS и CSS приложения и фиксированные версии
Bootstrap CSS и Tom Select с jsDelivr. Для картинок разрешены `data:` и `blob:`
для Bootstrap и предпросмотра. Атрибуты стиля разрешены для существующих
компонентов. Встроенные скрипты и обработчики событий запрещены в enforce.
Отчёты доступны в браузере. Серверный сбор CSP-отчётов не настроен.

После проверки своего домена и браузеров задайте `CSP_MODE=enforce` и
перезапустите сервис. При регрессии верните `report-only` на время диагностики.
JS и CSS на CDN остаются внешней зависимостью. Сбой CDN влияет на оформление
и селекты города. Проверку целостности CDN или локальную раздачу можно
добавить отдельно после сверки точных файлов.

## Журналы

Ошибка запроса получает идентификатор `X-Error-Id`. Приложение пишет контекст
и код ошибки. Настройте журнал прокси без Cookie, Authorization, тела запроса
и строк запроса. Ограничьте доступ к журналам, резервным копиям и файлам сессий.

Локальная проверка конфигурации запускается командой
`node tests/production.integration.js`. Тест использует `euromarket_test`
с применёнными миграциями. Для выпуска временного тестового сертификата нужен
OpenSSL. На Windows по умолчанию используется OpenSSL из Git for Windows.
Другой путь можно указать через `TEST_OPENSSL`.
