# EuroMarket — правила работы Codex

## Самостоятельная разработка
- Самостоятельно изучай относящиеся к заданию файлы.
- Пиши код, исправляй ошибки и запускай локальные проверки.
- Используй существующие технологии и структуру проекта.
- Не задавай лишних вопросов по обычным изменениям.
- Не изменяй файлы, не относящиеся к текущей задаче.

## Безопасность
- Не удаляй файлы, папки и данные без моего подтверждения.
- Не выполняй принудительные команды Git reset, clean и push --force.
- Не читай, не выводи и не отправляй секреты из .env без необходимости и разрешения.
- Не изменяй рабочую базу данных без согласования.
- Не выполняй DROP, TRUNCATE или массовые DELETE на рабочей базе.
- Для тестирования используй отдельную тестовую базу.
- Перед миграциями базы данных предложи план отката.
- Не публикуй изменения на сервер без моего разрешения.

## Проверка
- После изменения проверяй синтаксис и связанные тесты.
- Не удаляй существующие функции без необходимости.
- Проверяй авторизацию, права пользователей и безопасность запросов.
- Не выполняй разрушительные тесты на реальных пользовательских данных.

## Результат
После каждой задачи кратко сообщай:
1. Что изменено.
2. Какие файлы затронуты.
3. Какие проверки выполнены.
4. Какие проблемы остались.

## Экономия лимитов Codex

- Минимизируй расход контекста и количество инструментальных вызовов.
- Изучай только файлы, необходимые для текущего задания.
- Не сканируй весь проект без необходимости.
- Не читай node_modules, .git, dist, build и файлы журналов без необходимости.
- Не повторяй успешные проверки.
- Используй существующие функции и компоненты.
- Не устанавливай дополнительные библиотеки без необходимости.
- Объединяй связанные изменения в одну последовательность действий.
- Выполняй только необходимые тесты.
- Не создавай длинные отчёты.
- Не выполняй повторный анализ уже изученного кода без причины.
- После завершения сообщай кратко: что сделано, какие файлы изменены и какие проверки прошли.
- Не экономь на проверках безопасности и целостности данных.

Работай максимально самостоятельно в рамках доступных разрешений.

## Дополнительные правила

- Перед работой проверяй, не реализована ли запрошенная функция ранее.
- При небольших изменениях запускай только связанные тесты; полный `npm test` выполняй после крупных изменений или изменений общих компонентов.
- Не запускай повторно тесты, которые уже успешно прошли и не затронуты последующими изменениями.
- Если задача требует миграции, подготовь SQL-файл, проверь его на `euromarket_test`, но не применяй к `euromarket` без подтверждения.
